# 任意物体抓取功能包机器人适配简要说明

本文说明 `adaptive_object_grasping` 在当前机器人上如何取得必要参数，以及迁移到其他机器人时需要查询、测量和验证的内容。

## 1. 适配原则

参数来源按可信度分为三类：

1. **实时读取**：ROS 话题、TF、相机内参、关节状态和末端位姿。
2. **机器人模型**：URDF、SRDF、CAD/STL、厂商 SDK 和控制配置。
3. **实机标定**：相机光学外参、夹爪 TCP、控制值与实际开口宽度的关系。

模型中没有的数据不能靠猜测解锁真机。功能包默认保持：

```yaml
dry_run: true
allow_hardware_execution: false
```

硬件探针只有在相机、反馈和关键 TF 全部通过后才会报告 `ready=true`。

## 2. 当前机器人的参数来源

| 类别 | 当前机器人的获取方法 | 当前结果 |
|---|---|---|
| ROS 环境 | 读取厂商进程环境变量 | ROS 2 Jazzy、Domain 0、CycloneDDS、回环接口、机器人编号 283 |
| RGB-D 图像 | 检查厂商共享内存并读取真实帧 | 640x480、60 FPS、彩色与深度对齐 |
| 相机内参 | 读取共享内存内参结构并发布 `CameraInfo` | 已取得 `fx/fy/cx/cy`，深度比例为 `0.001 m` |
| 相机安装链 | 查询 URDF、头部关节反馈和厂商 KDL 代码 | 可计算 `Link_Zero_Point -> Link_Camera_Head_Forehead` |
| 相机光学外参 | 查询 URDF、TF 和厂商视觉代码 | 只有名义光轴旋转，没有测量后的完整外参 |
| 机械臂自由度 | URDF、SRDF 和实时反馈 | 左右臂各 7 自由度 |
| 关节反馈格式 | `ros2 topic type/echo` 读取实时 JSON | 位置单位为度，同时包含速度、力矩、温度 |
| 末端位姿格式 | 读取实时 EEF 话题和厂商代码 | 位置单位为米，四元数顺序为 `[x,y,z,w]` |
| 机械臂命令格式 | 查询厂商订阅回调和示例 | `std_msgs/String` 中传递 JSON 位置与四元数 |
| 夹爪范围 | 厂商运行配置、示例和实时反馈 | `10` 为打开下限，`360` 为关闭上限 |
| 夹爪几何 | URDF 关节、mimic 关系和 v2.2 STL | 已得到左右夹爪完整机械模型 |
| 夹爪 TCP | 根据 URDF/STL 计算两指名义中心 | 可建立初始 TCP，最终值仍需实物校验 |
| 路径规划 | 查询节点、服务、安装包和配置文件 | 有厂商 IK/FK/RRT 服务；尚无完整 MoveIt 配置 |
| GraspNet | 检查包内环境、源码和模型目录 | 已有 `graspnetAPI`；baseline 与权重尚未安装 |

详细实测值见 `docs/HARDWARE_DISCOVERY.md`。

## 3. 迁移到其他机器人必须查询的项目

### 3.1 ROS 与通信

- ROS 2 发行版。
- `ROS_DOMAIN_ID`、RMW 实现和 DDS 网络配置。
- 机器人编号或话题后缀规则。
- 图像、深度、相机内参、关节反馈和末端反馈的话题名称与消息类型。
- 控制命令的话题、服务或 Action 类型。

常用只读命令：

```bash
printenv | grep -E 'ROS|RMW|DDS|ROBOT'
ros2 node list
ros2 topic list -t
ros2 topic type /some_topic
ros2 topic echo /some_feedback_topic --once
ros2 service list -t
```

必须确认数组顺序、单位、角度制/弧度制、四元数顺序和时间戳，不能只确认话题名称。

### 3.2 RGB-D 相机

必须取得：

- 彩色图像和对齐深度图。
- `width`、`height`、`fx`、`fy`、`cx`、`cy` 和畸变参数。
- 深度单位或 `depth_scale`。
- 彩色与深度是否已经对齐。
- 光学坐标系名称和坐标轴约定。
- 图像时间戳、帧号和实际帧率。

如果厂商没有标准 ROS 图像话题，需要编写只读桥接节点，将共享内存或 SDK 图像转换为 `Image` 和 `CameraInfo`。

### 3.3 相机到机器人基座的坐标链

头部相机会随关节运动，不应把相机到基座写成永久静态 TF。推荐拆分为：

```text
机器人控制基座
  -> 腰部/颈部关节链（URDF + 实时关节角）
  -> 相机机械安装链接
  -> 相机光学坐标系（固定手眼外参）
```

需要查找：

- URDF 中相机安装链接及其父关节。
- 头部和腰部关节名称、顺序、零点补偿。
- 厂商是否已有 KDL、Pinocchio 或 TF 正运动学实现。
- 相机机械链接到彩色光学帧的标定矩阵。

检查 TF：

```bash
ros2 run tf2_tools view_frames
ros2 run tf2_ros tf2_echo BASE_FRAME CAMERA_OPTICAL_FRAME
```

若最后一段不存在，应使用标定板、AprilTag 或手眼标定得到固定外参，不能只用大致安装尺寸替代精确标定。

### 3.4 机械臂与末端反馈

必须确认：

- 单臂自由度、关节名称、顺序和上下限。
- 关节位置单位和零点。
- 控制基座坐标系。
- 当前末端位姿对应的是腕部、法兰、夹爪基座还是工具中心。
- 末端位置单位、四元数顺序和左右臂字段。
- 控制接口是否提供 IK、FK、轨迹、速度控制和取消/急停能力。

优先复用厂商经过验证的接口。适配器应将功能包内部标准位姿转换为厂商消息，并在发送前检查工作空间、数据新鲜度和硬件锁。

### 3.5 夹爪与 TCP

需要查询：

- 夹爪类型、开合方向和最大开口宽度。
- 控制值的打开/关闭方向、有效范围、单位和力矩限制。
- 夹爪实时位置、速度、力矩或电流反馈。
- URDF/CAD 中腕部、夹爪基座、连杆和指尖几何。
- 电机控制值到实际指间宽度的映射。

TCP 推荐定义在两指实际夹持区域的中心：

```text
WRIST_OR_FLANGE -> left_grasp_tcp
WRIST_OR_FLANGE -> right_grasp_tcp
```

URDF/STL 可以计算名义 TCP，但更换指尖、安装误差和传动间隙会产生偏差。至少使用已知尺寸物体或标定工具验证一次位置和方向。若需要按物体宽度控制夹爪，应采集多个开合位置，拟合：

```text
夹爪控制值 <-> 实际指间宽度（米）
```

### 3.6 路径规划与控制器

若使用 MoveIt，需要检查或创建：

- 完整 URDF/SRDF 和左右规划组。
- 正确的末端执行器与 TCP。
- `kinematics.yaml`、`joint_limits.yaml`。
- OMPL 或其他规划流水线。
- Planning Scene 与碰撞模型。
- `ros2_control` 控制器或厂商轨迹桥接器。
- 关节状态发布和轨迹执行反馈。

若机器人只有厂商 IK/FK/规划服务，也可以先实现独立后端，但必须确认其碰撞检测、超时、取消和执行结果语义。

### 3.7 安全参数

每台机器人都要重新确定：

- 左右臂可达工作空间。
- 最大速度、加速度、夹爪力矩和跟踪距离。
- 预抓取距离、抬升距离、位置与姿态容差。
- 自碰撞、环境碰撞和奇异位形处理。
- 急停方式及首次实验人员站位。

旧机器人的工作空间和速度限制不能直接复制到新机器人。

## 4. 功能包中需要修改的配置

主要配置文件：

```text
config/hardware.yaml   # 相机、反馈话题、基座和三个关键 TF
config/motion.yaml     # 规划后端、工作空间、夹爪范围和执行安全参数
config/perception.yaml # 图像话题、模型和目标检测参数
```

若厂商消息格式不同，需要替换或扩展：

```text
adaptive_object_grasping_nodes/hardware_probe.py
adaptive_object_grasping_nodes/motion_executor.py
```

不要直接删除硬件检查；应为新接口实现等价的数据新鲜度、TF 和执行许可检查。

## 5. 推荐适配顺序

1. 只读连接 ROS 图，记录所有消息格式和单位。
2. 接通 RGB-D 图像、内参和时间同步，在 RViz 中检查点云。
3. 建立机器人基座到相机光学帧的动态坐标链。
4. 接通左右关节与末端反馈，不发送动作。
5. 从 URDF/CAD 建立名义 TCP，并完成实物校验。
6. 在仿真或 `dry_run` 中检查 GraspNet 候选位姿和坐标轴。
7. 接入 MoveIt 或厂商规划后端，先验证规划而不执行。
8. 使用轻质软物体、低速度、单臂和短距离进行首次真机测试。
9. 验证急停、取消、超时和目标移走后的 PBVS 停止条件。
10. 所有检查通过后，才允许修改硬件执行开关。

## 6. 最低验收条件

迁移完成至少应满足：

- RGB 与深度持续同步，三维反投影尺寸和方向正确。
- 静止机器人时，基座到相机和 TCP 的 TF 稳定。
- 转动头部后，相机 TF 随关节正确变化。
- 左右臂反馈顺序、单位与真实运动方向一致。
- TCP 在 RViz 中位于两指夹持区域中心。
- 规划轨迹不穿过机器人自身和环境模型。
- 不发送命令时系统始终保持只读。
- 任一反馈过期或 TF 缺失时，硬件执行自动锁定。

这份清单完成后，YOLO、PBVS、GraspNet 和规划模块才能在新机器人上共享同一套可信坐标与安全边界。
